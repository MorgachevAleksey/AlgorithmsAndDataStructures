Сортировка слиянием

Основана на идее "Разделяй и властвуй", а именно:
Рекурсивно делит массив на два, вплоть до пар по одному элементу (они отсортированны по определению) и сливает отсортированные

Сложность по времени:
O(n*log(n))
log2(n) разделений массива надвое, вплоть до массивов по одному элементу
n сравнений каждого элемента на каждом уровне
!Сложносить не зависит от случая - (всегда логарифмическая глубина рекурсии, всегда линейное слияние на каждом уровне)

Сложность по памяти:
O(n)
Выделяется - один вспомогательный массив-буфер длинной в исходный массив, и он используется на каждом уровне
Так же рекурсия (глубиной log 2(n)) тоже занимает память
!Для связных списков O(1) - просто переставляются ссылки, поэтому сорт. слиянием - лучший выбор для списков
Сложность по памяти - может быть узким местом этой сортировки, особенно в мобильной приложениях, где память критична

Устойчивость - сортировка устойчива, если не меняет порядок равных элементов
Сортировка слиянием устойчива - при равных мы берем левый элемент (который в первоначальном массиве стоял раньше)

Фактически - алгоритм сортировки сводится к двум задачам:
1. Рекурсивное разделение на подмассивы
2. Слияние 

Слияние:
- В новый массив 
Применяется в классической реализации сортировки
Используется третий результирующий массив-буфер 
- In-place с запасом
Т.к. не предусмотренно буфера для хранения элементов массива с запасом - нужно идти с конца!
Так же три указателя:
1. Последний элемент первого списка
2. Последний второго
3. Последний свободный в первом
Добавляем больший
После основного цикла копируем остаток второго в первый

Реализация сортировки слиянием

Фактически два массива которые надо слить это [left, mid] и [mid + 1, right] - находятся в одном массиве 

Поиск середины без переполнения:
(right - left) - сколько элементов между краями
(right - left) / 2 - сколько элементо от левого края до середины
left + (right - left) / 2 - реальный индекс середины

Реализация делится на вызываемый публичнный статичный метод и два вспомогательных:
1. Метод 
- проверки корректности данных
- копирования массива в буфер
- запуска сортировки
2. Вспомогательный метод, оркестрирующий сортировку:
- ищет текущую середину
- запускает себя рекурсивно для левой и правой половинок
- сливает их
3. Метод слияния
- сливает 2 отсортированных подмассива (половинки до середины и после) с помощью буферного (в который предварительно копируется переданный массив)

Для слияния двух списков:
- создать новый узел и дать на него ссылку текущему и результирующему
- поочередно сравнивать узлы начиная сначала
- добавлять меньший следующим текущему
- в конце итерации переключить текущий 
- вернуть результируй (следующий т.к. значение первого по умолчанию)
Фактически алгоритм точно повторяет стандартный
Но сложность по памяти будет O(1) - константная потому что создается единтсвенный новый узел списка

Сортировка слиянием для односвязного списка
Т.к. мы не можем найти середину с помощью индексов:
Мы ищем середину с помощью двух указателей slow\fast с начала списка
fast движется в два раза быстрее slow, и когда он доходит до конца, slow указывает на середину
